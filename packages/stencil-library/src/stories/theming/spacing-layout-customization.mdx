## Introduction

The Technway Design System employs a variety of CSS variables to control spacing and layout, including margin, padding, grid gaps, and other layout-related properties. These variables are defined globally and can be customized to meet the specific needs of a project.

### Default Spacing and Layout Variables

Below is a snippet of the core spacing and layout variables used in the design system:

code={`

  /* Spacings */
  --tnw-spacing-none: var(--spacing-none, 0);
  --tnw-spacing-xs: var(--spacing-xs, 10px);
  --tnw-spacing-sm: var(--spacing-sm, 15px);
  --tnw-spacing-md: var(--spacing-md, 20px);
  --tnw-spacing-lg: var(--spacing-lg, 40px);

## Customizing Spacing and Layout

To customize the spacing and layout across the project, the default spacing and layout variables should be overridden in global CSS or theme-specific files.

### Example: Customizing Container Width and Breakpoints

To adjust the container width and breakpoints throughout the application:

<Source
code={`
:root {${`\n`}
  --container-width: 80%;${`\n`}
  --breakpoint-md: 960px;${`\n`}
}
`}
language="css"
dark={true}
/>

By overriding `--container-width` and `--breakpoint-md`, the layout and responsiveness of the application can be modified to better align with design requirements.

---

## Best Practices for Spacing and Layout Customization

- **Consistency**: Global variables (`--tnw-...`) should always be used to ensure uniformity across the project.
- **Flexibility**: The layout should be designed to adjust gracefully across different screen sizes by leveraging breakpoints.
- **Accessibility**: Spacing and layout should be considered in the context of user accessibility, ensuring that elements are appropriately spaced for easy interaction.
- **Reuse**: Hardcoding spacing and layout values directly in components should be avoided; predefined variables should be utilized to maintain consistency.
